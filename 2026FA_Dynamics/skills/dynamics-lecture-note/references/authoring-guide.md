# MC2103 Dynamics 렉처 정리 노트 집필 규격

버전: 1.0

기준 샘플: `site/lecture01.html`(입문형), `site/lecture02.html`(장문·유도·문제풀이형)

목적: 영어 강의 수강이 어려운 학습자가 강의를 듣지 않아도 개념을 이해하고 영어 시험을 준비할 수 있는 독립형 학습 자료 제작

## 1. 자료의 역할

정리 노트는 다음 네 가지를 동시에 충족해야 한다.

1. **수업 대체:** 슬라이드의 문장을 번역하는 데 그치지 않고, 개념의 이유·관계·사용 상황까지 한국어로 설명한다.
2. **원본 보존:** 원본 PDF의 모든 슬라이드를 순서대로 포함한다. 제목, 구분, 영상 링크, 참고문헌처럼 설명할 내용이 적은 슬라이드도 생략하지 않는다.
3. **시험 대비:** 중요한 개념어, 상태 표현, 동사, 형용사를 `English(한국어 번역)` 형식으로 반복 표기하고, 예상 질문과 영어 답안 문장을 제공한다.
4. **근거 통제:** 슬라이드, 영상 스크립트, 편집자 보강을 구분한다. 자동생성 스크립트의 오인식은 슬라이드와 역학 문맥으로 교정하고 교정 근거를 남긴다.

## 2. 소스 우선순위와 충돌 처리

내용을 판단할 때 다음 순서를 적용한다.

1. 원본 강의노트 PDF의 수식·도표·문장
2. 해당 렉처의 영어 영상 스크립트와 화면 문맥
3. 강의 인덱스의 날짜·주차·링크
4. 표준 역학 정의와 편집자 보강

충돌 시 임의로 섞지 않는다.

- **스크립트 오인식:** 슬라이드에 정확한 용어가 있으면 슬라이드를 채택한다. 예: `widget parties` → `rigid bodies(강체)`.
- **일정 충돌:** Teams에서 보존한 강의 인덱스를 현재 운영 정보로 우선한다. 녹화 영상의 주차 안내는 당시의 개괄적 로드맵으로 표시한다.
- **근거 없는 세부사항:** 시험에 유용해도 강의 자료에 없는 내용이면 `시험용 보강` 또는 `편집자 보강`으로 명시한다.
- **판독 불가:** 추측하지 않고 `원문 판독 필요`로 표시한다.

## 3. HTML 정보 구조

노트는 클릭식 슬라이드 쇼가 아니라 한 방향으로 읽는 긴 문서다.

1. 강의 메타데이터: 렉처 번호, 주차, 날짜, 제목, 원본 PDF, 영상 링크
2. 전체 개요·개념 지도: 강의의 큰 구조와 현재 과목 전체에서의 위치
3. 핵심 개념 요약: 이 부분만 읽어도 해당 렉처의 정의, 관계, 가정, 풀이 흐름을 이해할 수 있는 독립형 요약
4. 원본 슬라이드별 섹션: PDF 순서와 1:1 대응하며 상세 설명의 분량을 요약 때문에 줄이지 않음
5. Summary 영상 처리: 실제 개념 복습인지, 향후 단원 로드맵·행정 안내인지 판별하여 통합하거나 별도 섹션으로 구분
6. 시험 영어 표현: 정의형·비교형·이유형 문장
7. 핵심 용어집: `English(한국어 번역)` + 한 문장 정의
8. 출처와 스크립트 교정 기록

### 3.1 상단 영상 버튼 규칙

- hero(상단 표지)의 바로가기에는 실제 본강의인 모든 `Contents` 영상과 `Problem Solving` 영상만 순서대로 넣는다.
- `Contents 1`, `Contents 2`처럼 본강의가 여러 편이면 일부만 대표로 두지 않고 전부 표시한다.
- 모든 `Contents`와 `Problem Solving` 버튼은 동등한 본강의 바로가기이므로 전부 `button--primary` crimson(크림슨)으로 표시하며, 특정 영상 하나만 강조하지 않는다.
- `Overview`와 `Summary` 영상은 상단 바로가기에서 제외하고, 본문 근거와 하단 출처 목록에서만 제공한다.
- 영상 버튼 뒤에는 해당 렉처의 중립색 `원본 PDF 다운로드` 버튼과 `강의 목록` 버튼을 순서대로 둔다.

### 3.2 원본 PDF 다운로드 규칙

- 공개 사이트의 `downloads.html`에는 Lecture 01–16 원본 PDF를 모두 렉처별 카드로 제공한다.
- 각 카드에는 강의 인덱스에 근거한 week(주차), date(날짜), title(제목), page count(페이지 수), file size(파일 크기)를 표시한다.
- 링크에는 원래 파일명을 유지하는 `download` 속성과 `type="application/pdf"`를 사용한다.
- Lecture 16은 Lecture 12 바로 아래에 `Week 12 추가 강의 · 날짜 미기재`로 배치한다. 별도 날짜를 추정하지 않는다.
- Week 08은 `Midterm — No class`와 `날짜 미기재`만 안내하고, 존재하지 않는 PDF 항목을 만들지 않는다.
- 각 렉처 HTML의 hero(상단 표지)에도 해당 원본 PDF 직접 다운로드 버튼을 둔다. 이 버튼은 본강의 영상 버튼과 혼동되지 않도록 중립색으로 유지한다.
- 원본 PDF가 이미 공개 저장소의 `lecture_notes` 경로에 있으면 해당 파일의 GitHub raw URL을 직접 연결하고 배포 폴더에 중복 복제하지 않는다. 공개되지 않은 자료는 별도 승인 없이 링크하거나 업로드하지 않으며, `private-materials` 등 비공개 보관 경로는 절대 배포하지 않는다.

## 4. 원본 슬라이드 배치 규칙

- 각 PDF 슬라이드는 반드시 독립된 `<section class="source-section">`에서 시작한다.
- 모든 원본 슬라이드 이미지는 같은 컨테이너, 같은 종횡비 `16:9`, 같은 최대 너비, 같은 테두리와 캡션을 사용한다.
- 이미지는 `1920 × 1080` 기준으로 생성하고 브라우저에서는 `width: 100%`로 축소한다. 작은 썸네일로 사용하지 않는다.
- 한 슬라이드의 설명이 길면 같은 섹션 안에 `continuation-card(보충 설명)`를 추가한다. 추가 카드에는 슬라이드 이미지를 반복하지 않는다.
- 설명할 내용이 없는 링크·구분·참고문헌 슬라이드는 이미지와 최소한의 식별 정보만 둔다. 억지 해설을 만들지 않는다.
- 슬라이드에 포함되지 않은 overview(개요), recap(복습), glossary(용어집)는 `editorial-section(편집 섹션)`으로 분리한다.

## 5. 설명 작성 규칙

각 개념 슬라이드에는 필요한 범위에서 다음 블록을 사용한다.

- **핵심 해설:** 슬라이드와 스크립트를 합친 한국어 설명
- **왜 중요한가:** 이후 공식·문제풀이에서 이 개념이 맡는 역할
- **구분 기준:** 비슷한 개념과의 차이
- **시험 문장:** 영어로 정의하거나 비교할 때 바로 쓸 수 있는 문장
- **오해 방지:** 흔한 번역 오류, 부호, 전제, 범위 제한
- **출처 표시:** `슬라이드`, `Contents 영상 00:00`, `편집자 보강` 등의 근거 꼬리표

본문은 목록만 늘어놓지 않는다. 먼저 완전한 문장으로 개념을 설명하고, 표나 목록은 비교·암기·절차에만 사용한다.

### 5.1 핵심 개념 요약 규칙

- `핵심 개념 요약`은 목차와 슬라이드별 설명을 단순히 나열한 축약본이 아니다. 렉처의 핵심 질문, 개념 관계, modeling assumption(모델링 가정), 사용하는 원리, 문제 해석 흐름이 하나의 설명으로 연결되어야 한다.
- 시간이 부족한 독자가 요약만 읽어도 해당 렉처의 중심 내용을 이해할 수 있어야 한다. 다만 요약을 추가했다는 이유로 원본 슬라이드별 상세 설명을 줄이거나 삭제하지 않는다.
- 요약의 근거는 해당 렉처의 원본 슬라이드와 실제 개념 설명 스크립트다. 여러 슬라이드의 내용을 재구성할 수 있지만, 강의 자료 밖의 보강은 `시험용 보강` 또는 `편집자 보강`으로 표시한다.
- 핵심 영어 명사·상태·형용사·문제 지시 표현은 요약에서도 `English(한국어 번역)` 형식으로 반복한다.

### 5.2 Summary 영상 분류 규칙

1. 먼저 Summary 영상이 해당 렉처의 concepts(개념)를 실제로 recap(복습)하는지 확인한다.
2. 실제 개념 복습이라면 원본 슬라이드와 대조한 뒤 `핵심 개념 요약`의 보조 근거로 사용한다.
3. 향후 단원 roadmap(로드맵), 일정, 과제, 환영 인사 등 현재 렉처 요약과 다른 내용이라면 `핵심 개념 요약`에 섞지 않고 내용에 맞는 제목의 독립된 편집 섹션으로 둔다.
4. 영상 파일명이나 게시물 이름이 `Summary`라는 이유만으로 `강의 개념 요약`이라고 단정하지 않는다. 실제 자막 내용을 기준으로 분류한다.
5. 녹화본의 week(주차) 번호와 현재 강의 인덱스가 다르면 개념 흐름은 보존하되, 날짜를 추정하지 말고 현재 인덱스의 상태를 짧은 주의문으로 명시한다.

## 6. 이중언어 표기 규칙

### 6.1 반복 표기 대상

다음은 첫 등장뿐 아니라 문서 전체에서 계속 `English(한국어 번역)`로 쓴다.

- 핵심 명사: `dynamics(동역학)`, `kinematics(운동학)`, `kinetics(운동역학)`
- 상태·가정: `rigid(강체인)`, `deformable(변형 가능한)`, `negligible(무시할 수 있는)`
- 문제 지시 동사: `determine(구하라)`, `calculate(계산하라)`, `assume(가정하라)`, `neglect(무시하라)`
- 관계 표현: `under the influence of(…의 영향을 받아)`, `relative to(…에 대하여 상대적으로)`

### 6.2 반복하지 않아도 되는 항목

일반 접속사, 일상 단어, 이미 수식 기호로 명확한 숫자·단위는 억지로 병기하지 않는다. 모든 단어를 이중언어로 만들면 문장이 학습 자료가 아니라 괄호 지옥이 된다.

### 6.3 문장 예시

- 권장: `A rigid body(강체) does not deform(변형하지 않는다) under applied forces(작용력).`
- 비권장: `강체는 힘 아래에서 변형하지 않는다.` — 영어 시험 표현을 연습할 수 없다.
- 비권장: `A(하나의) rigid(단단한) body(몸체)는...` — 의미 단위가 파괴된다.

## 7. 자동생성 스크립트 처리

1. 타임스탬프별로 슬라이드 전환 지점을 찾는다.
2. 고유명사·전문용어·법칙 이름을 슬라이드와 대조한다.
3. 문법이 깨져도 의미를 임의로 확장하지 않는다.
4. 확실한 교정은 `ASR 교정 기록`에 원문 조각과 채택 용어를 적는다.
5. 확신할 수 없는 부분은 본문 근거로 사용하지 않는다.
6. 강사의 반복·말버릇·음악 표시는 제거하되, 예시와 범위 제한은 보존한다.

## 8. 디자인 규격

`design_reference/crimson2.md`에서 웹 문서에 적합한 규칙만 채택한다.

### 유지

- 단일 기능색 `#BF2B25` crimson(크림슨)
- `#171717` ink(잉크색)과 중립 회색 단계
- Pretendard 우선 글꼴 체계
- 4px 배수 간격, 얇은 경계선, 약한 다중 그림자
- 문장형 제목, 제한된 글자 굵기 400–700
- 배경용 prismatic gradient(프리즘 그라디언트)는 표지 영역에만 제한

### HTML에 맞게 변경

- 고정 `1280 × 720` 캔버스와 절대 좌표는 제거한다.
- 페이지마다 하단을 억지로 채우는 규칙은 제거한다.
- 고정 슬라이드 footer(바닥글)와 페이지 번호 대신 sticky navigation(고정 탐색)과 scroll progress(스크롤 진행률)를 사용한다.
- 본문은 `max-width`를 적용하고 모바일에서 한 열로 재배치한다.
- 원본 슬라이드만 `16:9`를 엄격히 유지하며, 설명 영역 높이는 내용에 따라 늘어난다.

## 9. 접근성·공개 배포 규칙

- 모든 원본 슬라이드 이미지에 슬라이드 번호와 제목을 포함한 `alt`를 넣는다.
- 링크 텍스트만 읽어도 목적지를 알 수 있게 한다.
- 핵심 내용은 JavaScript 없이도 읽혀야 한다.
- 모바일 가로 스크롤이 생기지 않아야 한다.
- 외부 공유 문서에는 제작 도구·캐릭터·사적 농담·사용자 개인정보를 넣지 않는다.
- 공개 전에 원본 강의자료와 영상 링크의 공개 범위를 확인한다. URL이 링크 전용이면 URL을 변형하거나 재업로드하지 않는다.

## 10. 렉처별 제작 절차

1. 인덱스에서 렉처 번호, 날짜, 영상 링크를 확인한다.
2. PDF 페이지 수와 종횡비를 확인하고 전 페이지를 이미지로 렌더링한다.
3. 전 페이지를 시각 검토하고 텍스트를 추출한다.
4. 영상별 영어 스크립트를 읽고 슬라이드별 타임스탬프를 매핑한다.
5. ASR 오인식 목록을 만든다.
6. 전체 개요·개념 지도와 독립형 핵심 개념 요약을 먼저 쓴다.
7. 모든 슬라이드 섹션을 순서대로 작성하고, 요약 때문에 상세 설명을 축소하지 않는다.
8. Summary 영상을 실제 내용에 따라 개념 복습 또는 별도 로드맵·안내 섹션으로 분류한다.
9. 시험 영어, 용어집, ASR 교정 기록과 출처를 추가한다.
10. `site/lecture01.html`과 `site/lecture02.html` 중 내용 유형에 가까운 완성본의 DOM 구조와 공통 CSS 클래스를 재사용한다.
11. 이전 완성 렉처와 비교해 용어 번역, 블록 순서, 이미지 크기, 색상, 모바일 폭을 검증한다.

## 11. 완성 판정 체크리스트

- [ ] 원본 PDF 페이지 수와 HTML의 `.source-section` 수가 일치한다.
- [ ] 모든 슬라이드 이미지가 순서대로 존재하고 `16:9`다.
- [ ] 링크·구분·참고문헌 슬라이드가 누락되지 않았다.
- [ ] 스크립트 오인식을 슬라이드와 대조했다.
- [ ] 중요한 영어 용어와 상태 표현이 반복 병기된다.
- [ ] 핵심 개념 요약만 읽어도 렉처의 정의, 개념 관계, 가정, 전체 풀이 흐름을 이해할 수 있다.
- [ ] 핵심 개념 요약을 추가한 뒤에도 슬라이드별 상세 설명이 유지된다.
- [ ] Summary 영상을 실제 내용에 따라 개념 복습 또는 별도 로드맵·안내로 분류했다.
- [ ] 수업을 듣지 않아도 개념 간 관계와 과목 범위를 설명할 수 있다.
- [ ] 영어 정의형 답안과 핵심 용어집이 있다.
- [ ] 강의 자료 밖의 보강은 명시돼 있다.
- [ ] 모바일과 데스크톱 모두 가로 스크롤이 없다.
- [ ] 끊어진 내부 링크, 중복 ID, 누락된 이미지가 없다.
- [ ] 해당 렉처의 원본 PDF 다운로드 링크와 파일이 모두 존재하며 파일명이 일치한다.
- [ ] 공개 문서에 사적 설정이나 개인정보가 없다.
